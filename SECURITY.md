# Security Policy

## Reporting a vulnerability

Do not report suspected vulnerabilities in a public issue, discussion, or pull request.

For a public repository with private vulnerability reporting enabled, open its **Security** tab, select **Advisories**, and choose **Report a vulnerability**. If that option is unavailable, contact the repository maintainers privately using a contact method documented in that repository or on an owner's GitHub profile.

Include, when possible:

- the affected repository, component, and version or commit;
- steps to reproduce or a minimal proof of concept;
- the observed and expected behavior;
- the potential impact; and
- any suggested mitigation.

Avoid accessing, modifying, or retaining data that is not yours. Allow maintainers reasonable time to investigate and coordinate a fix before public disclosure.

## Supported versions

Each repository defines its own supported versions. Unless a repository states otherwise, only the latest code on its default branch should be assumed to receive security updates.
